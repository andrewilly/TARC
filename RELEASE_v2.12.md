# Release Notes — TARC STRIKE v2.12

**Release date:** 2026-10-08

## Changes Since v2.11

This release fixes two data-loss bugs in extraction, makes archives deterministic,
and turns `--threads` into working parallelism.

### Data-loss fixes

- **Duplicated files were never recreated on extraction** — `Engine::extract()`
  skipped every entry with `is_duplicate` set and nothing ever resolved
  `duplicate_of_idx`, so identical files vanished from the output while the
  command still reported `Extract completed successfully`. The extractor now
  resolves the duplicate chain (with a cycle guard) and writes each duplicate
  while the original's chunks are being read. It also works when a filter
  selects the duplicate but not its original, and for duplicates with the same
  name as the original. Archives whose `duplicate_of_idx` is out of range or
  forms a cycle are rejected as `InconsistentToc`.
  The empty-file case was the worst: XXH64 of empty input is constant, so every
  empty file after the first was marked a duplicate and silently dropped.
- **`--force` had no effect and existing files were silently truncated** —
  `ExtractOptions::overwrite` was never read by the engine. Extraction now skips
  an existing destination file with a warning (`--force` overwrites it), and
  creating an archive — or the SFX output — over an existing file is refused
  without `--force`.
- **Archives were not byte-reproducible** — `FileEntry` was default-initialized,
  so `comp_size` and `duplicate_of_idx` were written from uninitialized memory
  (`comp_size = 105553127374848` for a 100-byte file). `Entry` is now
  zero-initialized and every field is set explicitly; `comp_size` holds the
  on-disk size of the chunk that contains the entry.

### Correctness

- **A truncated or corrupted archive could pass as valid** — `read_next_block()`
  returned the same error for the end marker and for a corrupt chunk, so an
  archive cut short could end with `Extract completed successfully`. The end
  marker is now reported separately and missing data always fails extraction.
- **`tarc -t` reported failure on archives made only of empty files** —
  `bytes_out == 0` was treated as an error.
- **`solid_mode` was ignored** — solid blocks were always enabled regardless of
  the option. With `solid_mode = false` each file now gets its own chunk.
- **Chunk checksums are always on**: `--verify` on creation now performs a full
  integrity pass over the new archive (opt-in; extraction-time verification is
  unchanged and still on by default).

### Performance

- **`--threads N` never parallelized anything** — only a single `std::future`
  existed and each chunk was awaited before the next was launched, so
  `g_active_workers` could never reach the limit, the wait loop was dead code
  and `N >= 3` behaved exactly like `N = 1`. Chunks now queue in a FIFO of
  futures, are written back in order, and the pipeline depth is bounded by the
  available RAM (each in-flight chunk holds an uncompressed buffer).
  Measured 1.65x on LZMA over 360 MB with 4 threads; the archive is
  byte-identical for any thread count.

### Security

- **`TOC file_count` was not validated** — a 20-byte header could make the reader
  reserve hundreds of gigabytes in one allocation. It is now checked against the
  actual file size.
- **Predictable SFX temporary files** — SFX archives were extracted to fixed
  paths in the system temp directory, open to a symlink attack. Names are now
  generated by `mkstemp` (`GetTempFileName` on Windows), the trailer is
  validated before the temporary file is created, truncated payloads are
  detected, and the file is removed on error.
- **`--force` on extraction** closes the silent-overwrite path described above.

### Bug fixes

- Two `FILE*` leaks: `write_chunk_streaming()` never closed the source file and
  `write_chunk_store_streaming()` discarded it with `release()`.
- `--sfx` produced a file without the executable bit on POSIX, so the
  "standalone executable" refused to start until `chmod +x`.

### Documentation

- **`Entry` is 48 bytes, not 44** — `STRK_SPEC.md` documented a 44-byte entry
  with a 32-bit timestamp. Verified at byte level: the file name starts at +48
  and the TOC ends exactly at EOF. Corrected the field table, the `comp_size`
  semantics, the `file_count` validation rule and the deduplication section.
  An independent implementation written against the old spec could not have read
  any `.strk` archive.
- README, `tarc.1`, `docs/usage.md`, `docs/development.md`, `docs/index.md` and
  the CLI help now describe what the code actually does (`--force`, `--verify`,
  `--threads`, test count, CI description).
- The SIMD claim was reworded: `include/simd_opt.h` performs real runtime CPU
  detection, but the engine does not currently route its buffer copies through
  it, so the README no longer advertises SIMD acceleration.
- Removed the reference to the deleted license module.

### Tests

- 11 new regression tests, one per fixed bug: dedup with different names,
  duplicated empty files, no overwrite without `--force`, existing archive not
  clobbered, byte-for-byte determinism, `solid_mode` off, corrupted chunk,
  absurd `file_count`, post-create verification preserving the stats, executable
  SFX with a valid trailer, test mode on empty-only archives.
- Suite is now **49 test cases / 250 assertions** (was 38 / 191).

### Version

- Version bumped to **2.12** across all source and build files.

## Building

```bash
# macOS
brew install zstd lz4 xz brotli
make

# Linux (Debian/Ubuntu)
sudo apt install libzstd-dev liblz4-dev liblzma-dev libbrotli-dev
make

# Windows (MinGW)
pacman -S mingw-w64-x86_64-{zstd,lz4,xz,brotli}
make
```

## Testing

```bash
make test          # 49 test cases, 250 assertions
make ASAN=1 test   # Compile and run with AddressSanitizer + UBSan
```
